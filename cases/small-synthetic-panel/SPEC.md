# Small case — synthetic panel

A trivial scenario of our own that crosses every component once: HTTP upload validation, storage,
the inspection loop over MCP, the policy, the trace, and asset memory. If it fails, the fault is in
coordination, deployment, or the contract — not in the difficulty of the image.

Derived from [docs/BRIEF.md](../../docs/BRIEF.md) and the HTTP contract in
[docs/BACKEND.md](../../docs/BACKEND.md). The checks were written from these documents, not from the
implementation.

## Actors

- A1. Operator — uploads two generated captures of one fresh asset.

## Inputs

Both images are generated by `checks.py` with the standard library, 256 × 256, 8-bit grayscale PNG:

- **sharp** — a checkerboard of 16-pixel squares at levels 60 and 190: high Laplacian variance, mid
  brightness, nothing clipped.
- **flat** — every pixel at 128: Laplacian variance 0.

Every run uses a new asset ID `case-small-<10 hex>`, so no reset endpoint is needed.

## Requirements

- R2. A capture that is too blurred is refused with a recapture instruction and memory is not
  touched. (BRIEF R2)
- R6. Every branch shows the metric, the measured value, and the threshold that chose it. (BRIEF R6)
- R9. The asset keeps a history. (BRIEF R9)
- R10. Only a failed run can be retried. (BRIEF R10)
- R14. The service reports its calibration and runs without a login. (BRIEF R14)

## Acceptance examples

- AE1. Given a fresh asset with the sharp capture as its first baseline, when the flat capture is
  inspected, then the trace holds a `recapture` decision with an `input_metric`, a numeric value, and a
  numeric threshold. (BRIEF AE1, generalised to a generated image)
- AE11. Given the running service, when `/health` is requested, then it answers 200 with
  `ok: true` and a calibration whose branch is `aligned`. (BRIEF AE11)

## Runtime contract

| Item | Value |
|---|---|
| Base URL | argument to `checks.py`; `make dev` serves `http://localhost:8000` |
| Health | `GET /health` → `{"ok": bool, "calibration": decision}`, 503 when not `aligned` |
| Upload | `POST /inspections`, multipart fields `asset_id` (`^[a-z0-9-]{1,64}$`) and `image`; 303 to `/traces/{run_id}` |
| Execute | `POST /runs/{run_id}/execute`; 404 `run_not_found` for an unknown run |
| Trace | `GET /traces/{run_id}?format=json`; decisions carry `input_metric`, `value`, `threshold`, `branch` (field names from the field manual, `docs/index.html`) |
| Retry | `POST /runs/{run_id}/retry`; a run that did not fail → `run_not_failed` |
| Reset | none; isolation by fresh asset ID |
| Error shape | `{"detail": string, "code": string, "retryable": false}` for non-HTML clients |

## Checks

| Check | Proves |
|---|---|
| `check_health_reports_aligned_calibration` | AE11 |
| `check_landing_names_the_product` | the public landing serves this product |
| `check_invalid_asset_id_is_refused` | 400 `invalid_asset_id` with the shared error shape |
| `check_undecodable_image_is_refused` | 400 `invalid_image` |
| `check_first_capture_becomes_the_baseline` | F1: a fresh asset's first usable capture ends `first_baseline`; its history page renders |
| `check_flat_capture_is_sent_back_with_its_number` | AE1 and R6 |
| `check_unknown_run_cannot_execute` | 404 `run_not_found` |
| `check_finished_run_cannot_be_retried` | R10: a finished run is refused with `run_not_failed` |

Run: `python3 cases/small-synthetic-panel/checks.py http://localhost:8000`. The summary line comes
first; exit 0 means every check passed, 1 a failure, 2 wrong usage.
